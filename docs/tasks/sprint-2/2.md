# Run automated frontend checks with Vitest and GitHub Actions

## Description

This task establishes automated frontend testing for PocketWatch using Vitest and React Testing Library.

The goal is to provide a repeatable testing environment for React components and integrate frontend validation into GitHub Actions. This allows developers to detect frontend regressions before merging changes into the main branch.

The task covers test configuration, an initial homepage smoke test, package scripts, and frontend CI integration. Backend unit testing and end-to-end browser testing are outside its scope.

## Specs
- Install Vitest, React Testing Library, jest-dom, jsdom, and the Vite React plugin.
- Create `apps/web/vitest.config.ts` to configure the testing environment.
- Configure Vitest to use jsdom for testing React components.
- Create `apps/web/vitest.setup.ts` to initialize jest-dom assertions and automatically clean up rendered components.
- Add frontend package scripts for running tests once and in watch mode.
- Create `apps/web/src/app/page.test.tsx` to verify that the homepage renders content.
- Update `.github/workflows/ci.yml` to include a separate frontend validation job.
- Configure frontend CI to run TypeScript checks, unit tests, and a production build.
- Supply a placeholder `DATABASE_URL` during CI dependency installation to support Prisma client generation without requiring a running database.

## Requirements

- Use Vitest as the frontend testing framework.
- Use React Testing Library for component rendering and assertions.
- Ensure tests can execute independently of the backend application.
- Maintain existing backend CI functionality.
- Run frontend tests automatically through GitHub Actions.
- Ensure failed frontend tests produce a nonzero exit status.
- Avoid requiring a live PostgreSQL database for frontend testing.

## Acceptance criteria

1. Running `pnpm --filter @pocket-watch/web test` successfully discovers and executes frontend tests.
2. The homepage smoke test renders the `Home` component and verifies that the document body contains rendered content.
3. The test setup supports jest-dom assertions and automatically cleans up rendered components after tests.
4. GitHub Actions includes a separate frontend job that executes typechecking, frontend tests, and a production build.
5. Frontend CI dependency installation succeeds without requiring a running PostgreSQL database.

## Tests

- `apps/web/src/app/page.test.tsx` verifies that the homepage renders nonempty content.
- `pnpm --filter @pocket-watch/web test` executes the frontend unit tests.
- GitHub Actions runs frontend tests automatically during CI.
- Additional automated tests are needed to independently verify the remaining acceptance criteria under the sprint grading requirements.
