# Start PocketWatch frontend and backend with Docker Compose

## Description

This task establishes a reproducible local development environment for PocketWatch using Docker Compose. Developers should be able to start the Next.js frontend and NestJS backend together without manually launching each application.

The task includes Docker configuration, workspace integration, and setup documentation. Production deployment and database provisioning are outside its scope.

## Specs

- Create a root `Dockerfile` using Node.js 24 and pnpm 10.
- Create `compose.yaml` defining separate `web` and `api` services.
- Expose the frontend on port 3000 and backend on port 3001.
- Configure the containers to execute the correct pnpm workspace scripts.
- Create `.dockerignore` to exclude unnecessary files and local environment secrets.
- Support local development through mounted source directories.
- Update the README with Docker startup, shutdown, and troubleshooting instructions.

## Requirements

- Preserve the existing pnpm monorepo structure.
- Support both Next.js and NestJS applications.
- Allow developers to start both services using one Docker Compose command.
- Avoid committing sensitive environment variables.
- Maintain compatibility with existing non-Docker development workflows.

## Acceptance criteria

1. Running `docker compose up --build` successfully builds and starts both application containers.
2. Running `docker compose ps` shows the frontend mapped to port 3000 and backend mapped to port 3001.
3. Backend container logs confirm that the NestJS application starts successfully.
4. Docker containers execute the correct pnpm workspace scripts for their respective applications.
5. The README documents the steps required to start, inspect, and stop the Docker development environment.

## Tests

- Manually verify container startup using `docker compose up --build`.
- Verify service status and port mappings using `docker compose ps`.
- Inspect backend startup logs using `docker compose logs api`.
- Automated tests validating the Docker configuration should be added to satisfy the sprint's test-file requirements.
