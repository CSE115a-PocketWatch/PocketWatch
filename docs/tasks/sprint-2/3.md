# Run automated backend checks with Vitest and GitHub Actions

## Description

This task establishes automated backend testing for PocketWatch using Vitest and the NestJS testing utilities.

The goal is to provide a repeatable testing environment for the NestJS API and run backend tests in GitHub Actions. This allows developers to detect backend regressions, starting with sign-in security, before merging changes into the main branch.

The task covers test configuration, package scripts, initial unit tests for refresh-token encryption and the session guard, and backend CI integration. Frontend testing, end-to-end testing against a running server, and tests that need a real database are outside its scope.

## Specs
- Install Vitest, `@nestjs/testing`, `unplugin-swc`, and `@swc/core`.
- Create `apps/api/vitest.config.ts` to configure the testing environment.
- Configure Vitest to use the Node environment and compile tests with SWC so NestJS decorator metadata and dependency injection work.
- Add backend package scripts for running tests once and in watch mode.
- Exclude test files from the `nest build` output.
- Create `apps/api/src/auth/token-crypto.spec.ts` to verify that refresh tokens are encrypted and decrypted correctly, and that wrong keys and tampered values are rejected.
- Create `apps/api/src/auth/session.guard.spec.ts` to verify that `SessionGuard` rejects requests without a valid session and allows requests with one, using a mocked `AuthService`.
- Update the Backend Checks job in `.github/workflows/ci.yml` to run backend tests after typechecking and before the build.

## Requirements

- Use Vitest as the backend testing framework, matching the frontend.
- Use `@nestjs/testing` to build test modules with mocked providers.
- Ensure tests can run without a live PostgreSQL database or real Google credentials.
- Maintain existing backend typecheck and build steps in CI.
- Run backend tests automatically through GitHub Actions.
- Ensure failed backend tests produce a nonzero exit status.
- Do not change the behavior of existing auth code.

## Acceptance criteria

1. Running `pnpm --filter @pocket-watch/api test` discovers and executes the backend tests and exits with status 0 when they pass.
2. The backend test command exits with a nonzero status when a test fails.
3. A token encrypted with `encryptToken` decrypts to the original value with `decryptToken`, and encrypting the same token twice produces different results.
4. `decryptToken` throws an error when given the wrong key or a tampered value.
5. `SessionGuard` rejects a request with no session cookie, or with an invalid or expired session, by throwing `UnauthorizedException`.
6. `SessionGuard` allows a request with a valid session and sets `req.user` to the signed-in user.
7. The Backend Checks job in GitHub Actions runs the backend tests on every pull request to `main`.
