# Run automated backend checks with Vitest and GitHub Actions

## Description

This task establishes automated backend testing for PocketWatch using Vitest and the NestJS testing utilities.

The goal is to provide a repeatable testing environment for the NestJS API and run backend tests in GitHub Actions. This allows developers to detect backend regressions before merging changes into the main branch.

The task covers test configuration, package scripts, an initial test of the Nest testing setup, and backend CI integration. Tests for specific backend features, frontend testing, end-to-end testing against a running server, and tests that need a real database are outside its scope.

## Specs
- Install Vitest and `@nestjs/testing`.
- Create `apps/api/vitest.config.ts` to configure the testing environment.
- Configure Vitest to use the Node environment and to run `*.test.ts` and `*.spec.ts` files under `apps/api/src`.
- Add backend package scripts for running tests once and in watch mode.
- Exclude test files from the `nest build` output with `apps/api/tsconfig.build.json`.
- Create `apps/api/src/testing/test-setup.test.ts` to verify that a Nest testing module injects constructor dependencies and can replace a provider with a mock.
- Create `apps/api/test-fixtures/always-fails.test.ts`, a test that always fails, and verify that running Vitest on it exits with a nonzero status.
- Update the Backend Checks job in `.github/workflows/ci.yml` to run backend tests after typechecking and before the build.

## Requirements

- Use Vitest as the backend testing framework, matching the frontend.
- Use `@nestjs/testing` to build test modules with mocked providers.
- Ensure tests can run without a live PostgreSQL database or real Google credentials.
- Maintain existing backend typecheck and build steps in CI.
- Run backend tests automatically through GitHub Actions.
- Ensure failed backend tests produce a nonzero exit status.

## Acceptance criteria

1. Running `pnpm --filter @pocket-watch/api test` discovers and executes the backend tests and exits with status 0 when they pass.
2. Running Vitest on a failing test exits with a nonzero status.
3. A Nest testing module built with `Test.createTestingModule()` injects a service's constructor dependencies.
4. A Nest testing module can replace a provider with a mock, and the service that depends on it uses the mock.
5. The Backend Checks job in GitHub Actions runs the backend tests on every pull request to `main`.
