# Build the Student Preferences settings interface

## Description
Create a Student Preferences page under User Profile in PocketWatch. Students can configure their daily study limit, preferred session length, and available study days and hours.

This task covers the frontend interface, form validation, and local form state. Backend persistence, authentication, and database changes are out of scope and will be implemented in S3-T2.

## Specs
- `/profile/preferences` displays a Student Preferences form.
- The form contains numeric inputs for daily study limit and session length, measured in hours and minutes respectively.
- The weekday selector allows multiple days to be selected or deselected independently.
- Start and end time inputs accept 24-hour time values and display them in a user-friendly format.
- The selected time window applies to all selected weekdays.
- Save validates the form and invokes a preferences submission handler with the current values.
- Invalid values display validation messages without submitting.
- Cancel restores the initial form values without submitting.
- The form is implemented in `apps/web/src/features/student-preferences/`.
- The route is implemented in `apps/web/src/app/profile/preferences/page.tsx`.
- Tests mock the submission handler so they do not require a running backend.

## Requirements
- Use the existing Next.js App Router, React, and TypeScript setup.
- Follow the existing frontend project structure and styling conventions.
- Daily study limit and session length must be positive.
- At least one weekday must be selected.
- End time must be later than start time.
- Do not add database or backend functionality.
- Existing frontend functionality and tests must continue working.

## Acceptance criteria
1. Visiting `/profile/preferences` renders the study limit, session length, weekday selector, and time range inputs.
2. Selecting or deselecting a weekday updates its selected state without changing other weekdays.
3. Submitting valid preferences invokes the submission handler with the entered values.
4. Submitting zero or negative study durations displays validation errors and does not invoke the submission handler.
5. Submitting with no selected weekdays or an invalid time range displays validation errors and does not invoke the submission handler.
6. Clicking Cancel restores the initial preferences without invoking the submission handler.
