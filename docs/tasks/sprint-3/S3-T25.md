# Implement Student Preferences backend

## Description
Implement backend support for Student Preferences in PocketWatch. Students can save and retrieve their daily study limit, preferred session length, and available study days and hours.

This task covers the Prisma database model, authenticated REST endpoints, input validation, and backend unit tests. The frontend settings interface is implemented separately in S3-T24.

## Specs
- `GET /preferences` retrieves the authenticated student's saved preferences.
- `PUT /preferences` creates or updates the authenticated student's preferences.
- Preferences include daily study limit, session length, available weekdays, start time, and end time.
- The `StudentPreferences` Prisma model has a one-to-one relationship with `User`.
- Each student can have at most one preferences record.
- Default preferences include a 240-minute daily limit, 60-minute sessions, Monday–Friday availability, and a 09:00–21:00 time window.
- The backend uses Prisma `upsert` to create or update preferences.
- The endpoints are implemented in `apps/api/src/preferences/`.
- Unit tests mock Prisma operations and do not require a running database.

## Requirements
- Use the existing NestJS, TypeScript, and Prisma setup.
- Protect both endpoints using the existing `SessionGuard`.
- Identify students through `CurrentUser` rather than accepting a user ID from the request body.
- Daily study limit and session length must be positive integers.
- At least one available weekday must be selected.
- Available weekdays must be unique integers from 1 through 7.
- Start and end times must use valid 24-hour `HH:MM` values.
- End time must be later than start time.
- Invalid preference values must return HTTP 400.
- Include a Prisma migration for the new database table.
- Existing backend functionality and tests must continue working.

## Acceptance criteria
1. `GET /preferences` retrieves preferences associated with the authenticated student.
2. `PUT /preferences` creates a preferences record when none exists.
3. `PUT /preferences` updates an existing preferences record.
4. Submitting zero or negative study durations returns a validation error.
5. Submitting invalid or duplicate weekdays returns a validation error.
6. Submitting an invalid time format or time range returns a validation error.
7. Both endpoints use session-based authentication and the authenticated user's ID.
8. Backend unit tests pass and TypeScript typechecking succeeds.
9. The Prisma schema includes the StudentPreferences model and its database migration.
